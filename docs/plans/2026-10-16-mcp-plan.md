# MCP server: build plan

Spec: `docs/specs/2026-10-16-mcp-design.md`. Each task is test first (red, green), then
`mix precommit`, then one jj change. Tasks 1–4 make an empty but signed-in server; each
later task adds tools and can ship alone.

## 1. Token verification (`BurpeeTrainer.Mcp.Token`)

- `verify(token, config, jwks_fetcher) :: {:ok, %{sub, scopes}} | {:error, reason}`:
  signature against the issuer's JWKS (JOSE, already a dependency via `oidcc`), `iss`
  equals `OIDC_ISSUER`, `aud` contains `MCP_OIDC_AUDIENCE`, `exp` in the future (30 s
  leeway), `sub` present.
- JWKS: discovery from `OIDC_ISSUER/.well-known/openid-configuration`, cached by
  `Cache-Control` max-age (default 10 min), refetched once on an unknown `kid`. A small
  GenServer behind a behaviour, so tests inject a stub; no network in tests.
- Tests: valid token; wrong issuer, wrong audience, expired, bad signature, unknown `kid`
  then refetch, missing `sub`. Tokens signed in the test with a generated RSA key.
- Config: `MCP_OIDC_AUDIENCE` in `runtime.exs`; MCP is off (routes 404) when unset, so
  existing deploys are unaffected.

## 2. Resource metadata and the 401

- `GET /.well-known/oauth-protected-resource`: `resource` (`<base>/mcp`),
  `authorization_servers: [OIDC_ISSUER]`, `scopes_supported`, `bearer_methods_supported:
  ["header"]`.
- Plug `BurpeeTrainerWeb.McpAuth`: Bearer → `Token.verify` → `Accounts` user by
  `oidc_sub` → assigns `current_scope`. Any failure: 401 with
  `WWW-Authenticate: Bearer resource_metadata="<base>/.well-known/oauth-protected-resource"`;
  unknown `sub` is a 401 too (no account creation). Never logs the token.
- Pipeline `:mcp` in the router: `accepts json`, no session, no CSRF.
- Tests: metadata body; each failure from task 1 gives the 401 and header; a valid token
  for an unknown `sub` gives 401; a valid token reaches the controller as that user.

## 3. JSON-RPC endpoint (`BurpeeTrainerWeb.McpController`, `BurpeeTrainer.Mcp`)

- `POST /mcp`, Streamable HTTP, stateless, `application/json` responses only; `GET /mcp`
  → 405. Batches refused.
- `initialize` (protocol version, `capabilities: tools, prompts, resources`, server info),
  `notifications/initialized` → 202, `ping`, `tools/list`, `tools/call`, `prompts/list`,
  `prompts/get`, `resources/list`, `resources/read`.
- `BurpeeTrainer.Mcp` holds the tool registry (a list of `Coach.Tool` modules) and maps
  `{:ok, map}` to a `text` content block of JSON plus `structuredContent`, and
  `{:error, msg}` to `isError: true` (a tool failure, not a JSON-RPC error).
- Arguments are validated against the tool's schema before `call/3` (reuse what
  `Coach.Agent` does).
- Tests: initialize handshake; unknown method −32601; unknown tool; invalid arguments
  refused with no effect; `tools/list` equals the registry.

## 4. Coach context, prompt and format resource

- Tool `get_coach_context` → `AgentPrompt.context(scope, slot)` with the current slot.
- Prompt `coach`: `Voice.text/0`, the glossary and planner rules from `AgentPrompt`
  (extract the module attributes into public functions so both use them), and the
  instruction to keep the shared memory with `update_memory`.
- Resource `burpee://workout-format`: generated from `WorkoutRequest.json_schema/0`,
  `WorkoutLayout`, `Levels` (landmarks per type).
- Tests: context equals `AgentPrompt.context/2`; prompt contains `Voice.text/0` and the
  landmarks; resource lists every `WorkoutRequest` field.

## 5. Week, progress, history

- `get_week`: `WeekWindow.lay_out/2`, minutes against the contract, `History.streak/1`,
  current level.
- `get_progress`: `ProgressGauges.for_types/4` and the per-type series Progress draws.
- `query_history`: new `Workouts.query_sessions(scope, filters, cursor)` (date range in
  the user's timezone, type, workout, tags, capture mode, reps range; 50 per page, cursor
  on `{completed_at, id}`), only authoritative completed sessions.
- `history_stats`: group by week or month, built on `History` and `Stats.Series`.
- Tests (property where pure): filters compose; paging covers each session once;
  stats equal Progress's numbers for the same sessions; another user's sessions never
  appear.

## 6. Memory and goals

- `list_memory`, `update_memory` (`Memory.apply_ops/2`; ops on an already forgotten note
  are skipped, which needs a small change and a test in `Memory`).
- `list_goals` (reuse `Tools.Goals`), `set_goal` (active immediately, through `Goals`),
  `confirm_goal`, `dismiss_goal`.
- Tests: guard limits hold through MCP; the Home coach section shows a note added through
  MCP (PubSub broadcast); goal set → `SummaryJob` queued.

## 7. Workouts

- `list_workouts` (library plus pacing style and pace), `get_workout` (request, layout,
  timeline summary).
- `create_workout`: request + layout → `PlanCompiler` → published plan; refusal carries
  the reason.
- `edit_workout`: publish the new plan, archive the old one, move any Home selection
  pointing at the old one, in one transaction.
- `archive_workout`: `Workouts.archive_plan/2`.
- Tests: `get_workout` → `edit_workout` unchanged gives an equal workout; impossible reps
  refused; edit moves the Home selection; a started session keeps its snapshot.

## 8. Sessions and the planner

- `log_session`: new `Workouts.log_session/3` (`source_kind: :manual`,
  `capture_mode: :logged`), queues `SummaryJob` and `PlanNextWorkoutJob`, not `MemoryJob`.
- `edit_session`: new `Workouts.update_session/3` (reps, duration, notes, tags, mood,
  feedback), queues `SummaryJob`.
- `delete_session`: `Workouts.delete_session/2`, queues `SummaryJob`.
- Migration: `coach_recommendations.planned_by` (`owner`, `claude`, `coach`, nullable).
  Set by the planner (`coach`), Home's own pick (`owner`) and `plan_next_workout`
  (`claude`). `PlanNextWorkoutJob` cancels with `:already_planned` for `owner`/`claude`.
- `plan_next_workout`: the current slot from `Policy.required_slot/2`, then `select` or
  `propose` through `Workouts.select_planned_workout/4` with a rationale checked by
  `Rationale.validate/1`.
- Tests: the job cancels for a Claude-planned slot and plans an unmarked one; a logged
  session queues summary and planner but not memory; edit and delete update Progress.

## 9. The coach permission

- Config `COACH_CLAIM` (default `burpee_coach`); `OidcController` sets `coach_enabled`
  from that claim at every sign-in (migration: boolean, default true, so nobody loses the
  coach before the claim exists). Verify with a real Pocket ID sign-in whether group
  custom claims arrive under `openid profile` or need another scope.
- `Coach.enabled?/1`, checked once in `Coach.Client.chat/2`: no model call and no budget
  for a user without the coach; every caller already handles `:provider_unavailable`.
- Home: the coach section renders without the form and pills when disabled, and only when
  there is a note, a Claude rationale or a memory change.
- Tool `set_coach_note` (`text`, `review`), broadcasting like the summary job.
- Tests: claim → flag (`true`, `"true"`, absent, `false`, another key); no job queued and queued ones cancel;
  Home with and without the coach; `set_coach_note` shows on Home.
